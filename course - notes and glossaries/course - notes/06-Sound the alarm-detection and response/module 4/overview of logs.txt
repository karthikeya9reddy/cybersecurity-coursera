Course 6 — Logs and Event Analysis
Google Cybersecurity Certificate · Quick Revision Notes
1. What are events and logs?
Event: An observable occurrence that happens on a network, system or device.

Examples:
- A user logging in.
- A file being deleted.
- A firewall allowing network traffic.
- An application generating an error.
Log: A record of events that occur within an organization's systems.

Log entry: An individual record describing one specific event.

Log analysis: The process of examining logs to identify events of interest.
Why are logs important?
Logs help security analysts answer the five Ws of incident investigation:
Question	Meaning
Who?	Who performed the action?
What?	What happened?
When?	When did it happen?
Where?	Where did it happen?
Why?	Why did it happen?

Logs help analysts build an incident timeline and understand what happened.
2. Types of logs
Log type	Generated by	Example
Network logs	Firewalls, routers, switches, proxies	Network traffic allowed or blocked
System logs	Operating systems	System errors, startup events
Application logs	Software applications	Application errors or activities
Security logs	Antivirus, IDS, IPS	Suspicious activity, file deletion
Authentication logs	Authentication systems	Successful or failed login attempts

Remember: Different devices and applications generate different types of logs.
3. Log details and verbose logging
A typical log contains:
- Date and timestamp
- Location or system information
- Action performed
- Author or user who performed the action
Example:
Login Event [05:45:15] User1 Authenticated successfully


Verbose logging records additional details beyond the default log entry.
Login Event [2022/11/16 05:45:15.892673]
User1 Authenticated successfully
from device1 (192.168.1.2)


Verbose logging provides more context, such as the device, IP address and precise timestamp.
4. Log management
Log management is the process of collecting, storing, analyzing and disposing of log data.
Four important aspects
Collection — Gather logs from different sources.


Storage — Store logs for access and investigation.


Analysis — Examine logs to identify events of interest.


Disposal — Dispose of logs according to retention policies.


What should organizations log?
Organizations should select log sources based on their security requirements and investigation needs.
Overlogging
Overlogging means recording excessive amounts of unnecessary information.

Disadvantages:
- Increased storage costs.
- Increased maintenance costs.
- System performance issues.
- Slower log searches.
- Important events become harder to identify.
Also, personally identifiable information (PII), such as names, email addresses and phone numbers, requires special handling.
Log retention
Log retention means keeping logs for a specified period.

Organizations may have legal or regulatory requirements.

Examples from your course:
- FISMA — Public sector.
- HIPAA — Healthcare.
- PCI DSS — Payment card security.
- GLBA — Financial services.
- SOX — Financial reporting and controls.
Log protection
Attackers may modify or delete logs to hide their activities.

One protection method is centralized logging:

Instead of storing logs only on individual devices, send them to a dedicated centralized log server.

This makes it harder for an attacker who compromises one device to modify the centrally stored records.

- Log forwarder: Software that collects logs from different sources and forwards them to a centralized repository.
- Aggregation: Bringing logs together in one location.
- Normalization: Converting different log formats into a consistent preferred format.
6. Understanding different log formats
This is one of the most important parts of your reading.

There are five formats covered in your material:
- JSON
- Syslog
- XML
- CSV
- CEF
A. JSON — JavaScript Object Notation
JSON is a lightweight, text-based format used to store and transmit data.

It uses:
- Key-value pairs.
- Commas.
- Double quotes.
- Curly brackets { }.
- Square brackets [ ].
Example:
{
  "Alert": "Malware",
  "Alert code": 1090,
  "severity": 10
}


Important concepts:
Component	Purpose
Key-value pair	Links a key with its corresponding value
Comma	Separates data
Double quotes	Enclose string values
{ }	Enclose an object
[ ]	Enclose an array

Example of an object:
{
  "User": {
    "id": "1234",
    "name": "user",
    "role": "engineer"
  }
}


The User object contains multiple properties.
B. Syslog
Syslog is a standard that can refer to a protocol, service and log format.
- Protocol: Transports logs to centralized log servers.
- Service: Receives and forwards log entries.
- Format: Structures log information.
Syslog uses three main components:
1. Header

Timestamp, hostname, application name and message ID.

2. Structured-data

Additional information organized into key-value pairs.

3. Message

Detailed description of the event.


Example:
<236>1 2022-03-21T01:11:11.003Z
virtual.machine.com evntslog - ID01
[user@32473 eventSource="Application"]
This is a log entry!


Important fields:
- Timestamp: 2022-03-21T01:11:11.003Z
- Hostname: virtual.machine.com
- Application: evntslog
- Message ID: ID01
- Structured-data: [user@32473 ...]
- Message: This is a log entry!
PRI (Priority): The value enclosed in angle brackets, such as <236>, indicates log priority. A lower numerical priority generally represents greater urgency.

Syslog ports:
Port	Purpose
514	Plaintext Syslog
6514	Encrypted Syslog

C. XML — eXtensible Markup Language
XML stores and transmits structured data using tags.

It uses three important concepts:
- Tags: Identify data using opening and closing tags.
- Elements: Include the tags and the data inside them.
- Attributes: Provide additional information about elements.
Example:
<Event>
    <EventID>4688</EventID>
    <Version>5</Version>
</Event>


Here:
- Event = Root element.
- EventID and Version = Child elements.
- 4688 and 5 = Element values.
Example of an attribute:
<Data Name="SubjectUserName">JSMITH</Data>


Here, Name="SubjectUserName" is an attribute.
D. CSV — Comma Separated Values
CSV uses commas to separate data values.

Example:
Date,Action,Source IP,Port,Protocol
2026-11-03,ALERT,192.168.1.5,80,TCP


Important points:
- Data fields are separated by commas.
- Field names may or may not be included.
- The position of each value corresponds to its field.
- Analysts need to understand the source's field ordering.
E. CEF — Common Event Format
CEF is a log format that uses pipe-separated fields and key-value pairs.

Its basic structure:
CEF:Version|Device Vendor|Device Product|
Device Version|Signature ID|Name|Severity|Extension


Example:
CEF:1|Security|threatmanager|1.0|100|
worm successfully stopped|10|
src=10.0.0.2 dst=2.1.2.2 spt=1232


Breakdown:
Field	Value
Version	1
Device Vendor	Security
Device Product	threatmanager
Device Version	1.0
Signature ID	100
Name	worm successfully stopped
Severity	10
Extension	Source IP, destination IP, source port

The extension contains additional information in key-value pairs.

Important: Syslog is commonly used to transport CEF logs. When combined, a Syslog timestamp and hostname can appear before the CEF message.
7. Quick comparison of all five formats
Format	How to recognize it
JSON	Curly brackets and key-value pairs
Syslog	Header + structured-data + message
XML	Tags and elements
CSV	Comma-separated values
CEF	Pipe-separated fields and key-value extension
