1. Introduction to Automation
Automation is the use of technology to perform repetitive tasks with minimal human intervention.

In cybersecurity, Python helps analysts automate security checks, process large log files, detect unusual activity, and manage access controls.
Benefits of automation
- Efficiency: Process large amounts of data quickly.
- Consistency: Apply the same security rules repeatedly.
- Accuracy: Reduce manual errors.
- Scalability: Monitor thousands of security events.
- Early detection: Identify suspicious activity sooner.
Automation supports security analysts but does not eliminate the need for human investigation.
2. Python Automation in Cybersecurity
Example 1: Login timeout policy
Scenario: A healthcare organization wants to flag login attempts that take more than three minutes.

Python can track the elapsed time between the start and completion of authentication.
login_duration = 190  # Secondsif login_duration > 180:    print("Login timeout exceeded")



Output:
Login timeout exceeded


Here, 180 seconds equals three minutes.

A real authentication timeout would need to be enforced by the authentication system, rather than only printing a message.
Example 2: Detect unusual login activity
A security analyst might flag login events involving unusual times, unauthorized locations, or unexpected simultaneous sessions.
login_hour = 2approved_location = Falseif login_hour < 6 or not approved_location:    print("Investigate login activity")



Output:
Investigate login activity


The code flags a login that happened before 6 AM or from a location not marked as approved.

These conditions are examples of organizational rules, not universal indicators of compromise.
Example 3: Detect repeated failed logins
Scenario: A company wants to flag users with more than three failed login attempts within 30 minutes.
failed_attempts = 4if failed_attempts > 3:    print("Suspicious login activity")



Output:
Suspicious login activity


In an actual monitoring system, the analyst's script would need to calculate the failed attempts within the specified time window using log timestamps.

Example: Count logins by a flagged user
This combines variables, loops, conditionals, functions, and lists.
def count_user_logins(usernames, flagged_user):    counter = 0    for username in usernames:        if username == flagged_user:            counter += 1    return counterlogin_records = ["alex", "mike", "alex", "zara", "alex"]result = count_user_logins(login_records, "alex")print("Total login attempts:", result)



Output:
Total login attempts: 3


How it works
1. The function accepts a list and a target username.
2. counter = 0 initializes the counter.
3. The for loop examines each username.
4. The if statement checks for a match.
5. counter += 1 increments the counter.
6. return counter sends the result back.
This counts occurrences in the supplied records. It does not distinguish successful logins from failed attempts unless that information is included in the data.

4. Working with Security Log Files
A log file records events that occur within a system, network, or application.

Security analysts use logs to investigate authentication activity, system errors, unauthorized access, and possible attacks.
Common log file formats
Format	Description	Example
.txt	Plain text with flexible structure	Authentication logs
.csv	Text data organized into comma-separated fields	Login activity records

Example .txt log
2026-11-22 10:30:15 admin login_failed
2026-11-22 10:31:20 alex login_success
2026-11-22 10:32:05 admin login_failed


Example .csv log
username,ip_address,status
admin,192.0.2.10,failed
alex,192.0.2.20,success
admin,192.0.2.10,failed


The CSV format organizes each record into fields, making automated analysis easier.

5. Introduction to CI/CD and DevSecOps
What is CI/CD?
CI/CD stands for:
- Continuous Integration (CI): Frequently integrating code changes and running automated checks.
- Continuous Delivery: Keeping validated software ready for release.
- Continuous Deployment: Automatically releasing changes that pass required checks.
What is DevSecOps?
DevSecOps integrates development, security, and operations so security is considered throughout the software development lifecycle.

Instead of checking security only before release, security checks can be integrated into the development and deployment pipeline.
Developer commits code

CI pipeline starts
Build, lint, and automated tests
Automated security checks
SAST, SCA, secrets scanning, and other checks
Release decision
Pass requirements or stop for investigation
Deployment
Release according to the approved pipeline

Python scripts can participate in these checks and control how their results affect a release.
6. Security Testing in CI/CD
Technique	Full name	Purpose
SAST	Static Application Security Testing	Examine source code or compiled artifacts for potential weaknesses
DAST	Dynamic Application Security Testing	Test the behavior of a running application
SCA	Software Composition Analysis	Identify vulnerable or problematic dependencies
Secrets scanning	Credential detection	Find accidentally exposed passwords, tokens, and API keys
Vulnerability scanning	Security weakness identification	Identify known vulnerabilities in systems or software components

SAST vs. DAST vs. SCA
SAST examines the application without needing to execute it.

DAST tests a running application, often in a controlled testing environment.

SCA analyzes third-party packages and dependencies.

These approaches complement each other; none guarantees that an application is free of vulnerabilities.
7. Other Security Automation Tasks
Automated vulnerability scanning
Python can coordinate vulnerability scans, process results, and generate alerts or reports.
Compliance checks
Scripts can check configurations against organizational policies and report violations.
Secrets management
Python scripts can interact with secrets-management systems and help detect credentials accidentally committed to code repositories.

Important: Avoid hardcoding secrets in source code or printing them in CI/CD logs.
Policy as Code
Policy as Code means expressing rules in a machine-readable form so automated systems can evaluate them.

Example:
critical_vulnerabilities = 2if critical_vulnerabilities > 0:    print("Release blocked")else:    print("Security check passed")



This illustrates a release policy. A production pipeline must also use the script's exit status or another supported mechanism to enforce a block.

Five essential rules
1. Combine variables, loops, conditionals, and functions to automate repetitive work.
2. Use timestamps and structured log data to investigate login activity accurately.
3. Use file handling to read security data rather than manually inspecting every entry.
4. Integrate security tests early in the CI/CD pipeline.
5. Test automation carefully, particularly when it can lock accounts or block software releases.
